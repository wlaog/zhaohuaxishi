# 用 Sakura Frp 从手机访问日记

Tailscale 原有功能保留，可以独立启停。Sakura 方式只需在电脑运行官方启动器，手机直接使用浏览器，通过日记密码登录。电脑需要在线、不休眠，并运行日记服务和 Sakura 隧道。

当前版本由官方启动器管理账号、节点、隧道和重连；日记控制台管理独立入口、HTTPS 地址和日记访问密码。控制台显示的“本机入口已就绪”不代表外网隧道已连通。

## 首次配置

1. 在 [Sakura Frp 官网](https://www.natfrp.com/)注册账号，根据官方提示完成账号准备。按照[官方安装指南](https://doc.natfrp.com/launcher/usage.html)安装 Windows 启动器。访问密钥只填到官方启动器，无需提供给日记应用或他人。
2. 在“朝花夕拾”电脑控制台找到“Sakura Frp · 密码登录”。保留独立入口端口 `8767`，如果占用则改用其他空闲端口；它必须与本地日记端口（通常 `8766`）不同。
3. 在 Sakura 创建 **TCP 隧道**。选择允许当前 Web 用途的节点，首次可从符合用途要求的非内地节点试起。填写本地 IP `127.0.0.1`、本地端口 `8767`（以控制台为准），记下平台分配的远程端口。**不要指向免登录的本地日记端口。** 节点要求以面板备注和[Web 穿透指南](https://doc.natfrp.com/app/http.html)为准；内地 HTTP(S) 隧道需要备案域名，不能把不同类型的规则混用。
4. 编辑隧道，开启“自动 HTTPS”。保持 HTTP 反代模式和默认转发头，不重写 Host。反代需要提供 `X-Forwarded-Proto: https`，较新官方 frpc 默认会添加。不要使用直通模式转发明文 HTTP。参考[自动 HTTPS](https://doc.natfrp.com/frpc/auto-https.html)与[用户手册](https://doc.natfrp.com/frpc/manual.html)。
5. 按[子域绑定指南](https://doc.natfrp.com/bestpractice/domain-bind.html)申请免费 `nyat.app` 子域名，绑定到该隧道。重启隧道，等待日志显示对应证书加载成功。也可使用自己的域名和有效证书。只有自动 HTTPS 开关而没有可信证书时，可能仍有证书错误；不要把跳过证书警告当成完成配置。
6. 在日记控制台填写完整的 `https://子域名:远程端口`，例如 `https://diary.example.invalid:23456`（示意地址，不能访问）。不要添加路径、账号、密码或查询参数。
7. 设置至少 12 个字符的**日记访问密码**，建议使用密码管理器生成。它与 Sakura 账号密码、启动器访问密钥相互独立。以后修改地址或端口时，密码留空会保留原密码。
8. 保存正在编辑的日记，然后点击“保存并开启入口”。应用配置会重启日记服务，保留日记和 Tailscale 配置。回到官方启动器启动隧道。
9. 手机关闭 Wi-Fi，使用移动网络打开完整 HTTPS 地址，确认看到日记登录页。输入日记密码，检查阅读和保存是否正常。电脑本机打开公网地址可能受网络回流影响，手机移动网络测试更能代表外网连接。

没有 Sakura 账号时，可以先完成本地代码与测试，但无法验证真实节点、额度、证书签发及运营商线路。套餐、流量、节点可用性以账号面板为准。

## 日常使用与排查

可配置独立备用隧道，主线路与备用线路分别绑定不同的 HTTPS 地址。服务配置中的 `additionalOrigins` 是备用地址的精确白名单（最多四个），两条线路共用同一份日记数据及访问密码，浏览器分别记住各域名的登录状态。修改主线路设置时保留备用地址；控制台显示备用地址并提供复制按钮。平台隧道仍需在官方启动器里分别开启，不自动迁移或切换 DNS。

- 登录在当前浏览器记住 30 天；服务重启、改密码或修改入口配置会使现有会话失效。登录过期时，应用弹出重新登录框，当前草稿不跳转、不清空。断网草稿仍仅保留在页面内存。
- 页面侧栏可“退出远程登录”，存在未保存草稿时先保存或导出。公共设备用完退出。
- “关闭入口”会关闭独立监听端口并撤销会话，保留地址和密码配置。不会停止 Sakura 启动器中的其他隧道；Tailscale 独立控制。
- “停止服务”会同时停止本地日记与 Sakura 日记入口，之后点击“启动并打开日记”即可按已保存配置恢复入口。
- 本机入口未就绪：检查日记是否启动、端口是否占用以及控制台日志。
- 外网打不开：检查启动器的隧道日志、节点状态、额度和远程端口，确认电脑不休眠。
- 返回访问地址或转发配置错误：检查完整 HTTPS 地址是否与隧道一致，是否保留 Host 和 `X-Forwarded-Proto`，以及是否指向独立入口端口。
- 密码错误多次：15 分钟内失败 5 次后，整个入口限制登录尝试，待失败记录超过 15 分钟后恢复，不按可以伪造的转发 IP 分配额度。已有会话仍可使用。
- 忘记密码：在本机控制台设置新密码；本地日记访问不需要此密码。

## 实现与验证

独立入口仅监听回环地址，但不会因连接来自本机而跳过认证。与本地/Tailscale 入口共用同一 `DiaryStore`、每日详情存储、写入 token 与变更版本。所有日记、归档资源和 API 均在认证后读取，保留 Origin 与写入 token 检查。

密码以带随机盐的 scrypt 摘要存放于 Git 忽略的 `local-state/sakura-access.json`。控制台给后台任务的临时输入通过 Windows 当前用户 DPAPI 保护，处理后删除；明文密码经标准输入传给摘要工具，不进入命令参数或日志。会话仅存服务内存，使用随机 Cookie（Secure、HttpOnly、SameSite=Strict），没有额外云端日记副本。

`npm test` 覆盖入口隔离、认证、限速、过期、退出、Tailscale 共存、共享存储、控制台生命周期与端口冲突。`npm run test:sakura:browser` 使用隔离的测试资料与本机 HTTPS 代理模拟官方自动 HTTPS，验证手机登录、自动保存、过期后保留草稿并重新登录、退出，截图在 `qa-output/sakura-browser/`；该测试不代表真实公网节点已验证。
